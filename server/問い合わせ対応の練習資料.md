# 問い合わせ対応の練習資料

0.9.0 / 2026年10月20日 / 学校祭ゲストWi-Fi / 運営者向けの案

この資料は担当者の机上練習用です。APを模擬したり、学校の機器を操作したりしません。現在の確認版は同意を保存するだけで、通信許可を発行しません。本番の接続案内はAP・回線・正式SSIDの確定後に更新してください。

## 最初の聞き取り

「どの画面で止まっていますか」「表示されたメッセージは何ですか」「ほかの場所でも同じ状態ですか」を確認します。本人に端末を操作してもらいます。パスワード、認証コード、秘密鍵、Cookie、閲覧履歴の提出を求めません。画面写真は他の通知や個人情報が入る可能性があるため、原則として必要なメッセージだけ文字で確認します。

問い合わせ票には発生日時（日本時間）、エリア、症状、表示メッセージ、対応担当、次の担当、結果を記入します。端末の種類とOS版は必要な場合だけ任意で確認します。受付番号は保存確認が必要な担当者だけが扱い、一般掲示や集計画面へ載せません。

## 事例と回答例

### 1. 接続の画面が出ない

回答例: 「会場で案内しているSSIDと同じか確認させてください。Wi-Fi設定の接続先と画面の状態を、ご自身で確認していただけますか。」

担当者は正式なSSID・案内先を確認します。未確認のURLやQRコードへ誘導しません。全ネットワーク設定の初期化、セキュリティ警告の無視、個人の通信設定の一括変更を求めません。複数人・同じエリアで起きる場合はネットワーク担当へ引き継ぎます。

### 2. 同意のチェックやボタンが押せない

回答例: 「規約の読み込みと受付状態を確認します。画面の下にあるメッセージを教えてください。文字を大きくして確認することもできます。」

読み込み中、提供期間外、受付停止、リンク期限切れを区別します。スクロールを終えれば必ず押せるとは説明しません。本人が条件を確認し、本人が同意のチェックを操作します。スタッフが代わりに同意しません。

### 3. 「保存結果を確認できません」と表示された

回答例: 「保存された可能性もあります。同じ画面の『再確認』から確認してください。何度も別の画面を開く必要はありません。」

同じ内容での再試行を案内します。連打、別の確認リンクでの繰り返し登録、保存記録の削除は行いません。規約変更や期限切れで続行できない場合は、保存結果を担当者が確認してから新しい案内を出します。

### 4. 保存済みだがインターネットにつながらない

確認版での回答例: 「同意の保存は確認できています。この確認版では、インターネットへの通信許可はまだ発行していません。」

本番時には、受付番号による保存確認と、AP・ルーター側での通信許可確認を別々に担当者が行います。保存成功だけで接続成功と判断しません。SSID、エリア、他の来場者への影響、機器側の状態をネットワーク担当へ渡します。

### 5. 「提供期間外」「受付停止」と表示された

回答例: 「現在の受付状態を担当者に確認します。画面を何度も開き直さず、この案内のまま少しお待ちください。」

正式な開催日時と日本時間を確認します。来場者の端末時計を変更させたり、担当者が終了日時を勝手に延長したりしません。提供が終了している場合は終了案内を示します。

### 6. 混雑していて遅い

回答例: 「混雑の状況を確認します。接続できている場合も、速度が下がることがあります。改善の時刻は、担当者の確認後にご案内します。」

保証していない速度や復旧時刻を約束しません。時間帯集計の同意4件を「4人接続中」と読み替えません。エリア、時刻、範囲を記録し、AP・回線の確認担当へ引き継ぎます。

### 7. 英語・やさしい日本語で案内してほしい

日本語例: 「上の言語から切り替えられます。やさしい日本語では案内を簡単にし、ルールの本文は元の日本語で表示します。」

English example: “You can choose English at the top of the page. If you need help, please ask event staff. You do not need to share your password or authentication codes.”

保存前の切り替えでは改めて規約の確認とチェックが必要です。保存後の切り替えは保存済みの版・言語を変更しません。規約について解釈や承認が必要な質問は、学校側の担当へ渡します。

### 8. 文字が小さい・色が見にくい・読み上げで操作したい

回答例: 「『大きく』や『高コントラスト』を試せます。キーボードの場合はTabで項目を移動できます。ご自身の操作に合わせてご案内します。」

規約を読まずに進むよう促しません。支援技術の音声・操作は実機確認が残っているため、必ず動くとは約束しません。読み上げの順番や名前で困った箇所を、本人が説明できる範囲で記録します。

### 9. 不審なSSID・QRコード・証明書の警告

回答例: 「入力を続けず、会場の正式な案内と一致するか確認します。パスワードや認証コードは入力しないでください。」

警告を無視して進める操作は案内しません。不審な掲示は担当者へ報告し、場所と時刻を記録します。来場者の画面・通信履歴を勝手に収集しません。

## 3人で行う練習

来場者役、受付役、観察役で、上の事例から一つ選びます。来場者役は架空の症状だけを伝え、受付役は聞き取りと回答を行い、観察役が次の項目を記録します。実際の同意・通信許可・設定変更は行いません。

| 確認項目 | 判定・メモ |
|---|---|
| 保存と通信許可を区別できた | 未記入 |
| パスワード・認証コード等を求めなかった | 未記入 |
| 本人の同意操作を尊重できた | 未記入 |
| 期限・混雑・障害を決めつけなかった | 未記入 |
| 次の担当と引き継ぎ内容が明確だった | 未記入 |
| 未確認の復旧時刻や速度を約束しなかった | 未記入 |

練習日、参加者、選んだ事例、改善点を記入してください。この資料の作成だけで担当者の練習が完了したとは扱いません。
