# 容量警告と管理画面

0.7.0 / 自動削除は停止を継続します。容量警告は管理画面の通知であり、外部メール等を送信しません。

## 容量の設定案

`plan-capacity`は現在のMySQL推定使用量・バックアップ合計・アプリ保存先の空き容量を読み取り、設定案だけを新しいファイルへ保存します。

| 対象 | 暫定の警告値 |
|---|---|
| MySQL推定使用量 | 現在量の4倍と1GiBの大きい方 |
| バックアップ合計 | 現在量の4倍と4GiBの大きい方 |
| アプリ保存先の空き容量 | 5GiBを下回った場合 |

これは予測や本番容量保証ではありません。MySQLサーバーのディスク空き容量、共用サービスの使用量、開催日数・記録量を確認してlimitsを見直してください。晴天3,000人+余裕500人=1日3,500人は来場者数であり、同時接続人数・同意件数・記録容量と同一には扱いません。雨天は1,900+500=2,400人が計画上の目安です。総容量の警告と単一ファイルの上限は別です。既存の画面によるバックアップ検証は暗号文256MiBまでなので、大きなバックアップの運用は別途見直しが必要です。

```powershell
.\.venv\Scripts\python.exe .\manage.py --home 'C:\FestivalWiFi\local-data' plan-capacity --output 'C:\FestivalWiFi\capacity-plan-新しい名前.json'
# 内容を確認し、必要ならlimitsの数値を修正。容量の単位はbytes。
.\operate.ps1 -DataDirectory 'C:\FestivalWiFi\local-data' -Action stop
.\.venv\Scripts\python.exe .\manage.py --home 'C:\FestivalWiFi\local-data' apply-capacity --plan 'C:\FestivalWiFi\capacity-plan-新しい名前.json'
.\operate.ps1 -DataDirectory 'C:\FestivalWiFi\local-data' -Action start
```

正しい保存先・作成時の設定ハッシュを照合し、古い案や別保存先への適用を拒否します。起動中状態とsupervisorのロックを確認し、停止後だけ適用します。手動起動したserve/workerも作業前に停止してください。別の設定編集と同時には実行しません。

configuration-historyに変更前・変更後の設定と案を残し、DB監査へ変更要求と変更完了を記録します。書き込み失敗では履歴・一時ファイルを消しません。要求だけが残った場合、現設定と履歴を照合し、勝手に完了と扱わないでください。再実行では新たに案を作ります。アプリとworkerは再起動時に新設定を読みます。

workerは約30秒ごとに警告を判定します。通知の確認済み操作は問題の解消とは別です。警告後もバックアップやログを削除せず、容量追加・承認された保管先への複製を進めます。過去記録を残し、条件が改善すると通知は解消状態になります。

## 管理画面の3つの表示

| 表示 | 内容 |
|---|---|
| 当日の運営 | 定期処理、通知、当日チェック、引き継ぎ、許可・取り消し |
| 記録・調査 | 同意出力、バックアップ、監査検索、障害調査資料 |
| 保守・設定 | 保存容量・増加傾向、追加認証、規約、MySQL診断、AP情報、管理者設定 |

役割に応じた項目だけを表示します。閲覧担当の記録・調査切り替えは無効です。画面の切り替えは入力を保持します。各項目の更新・再ログインによる破棄は従来の案内に従います。ボタンはキーボードで操作でき、選択状態と表示領域を関連付けています。表示切り替えは権限管理の代替ではなく、サーバー側の権限検査も継続します。
