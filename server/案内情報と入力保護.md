# 案内情報・入力保護・ログイン期限

0.10.0 / 2026年10月20日 / ローカル開発版 / MySQL専用

## 案内情報の一括管理

管理画面の「保守・設定 → 学校祭の案内情報」は設定管理権限で使います。学校祭名（日・英）、SSID、窓口（日・英）、受付開始・終了をまとめて確認します。正式情報は未確定です。空欄は来場者向けに未確定と表示し、正式会期の確認欄が未チェックならローカル試験用の日時は公開表示しません。英語が未入力なら日本語の正式表記を使用します。

保存は変更案の作成だけです。現在の画面や受付日時を即時変更しません。SSIDは案内用の文字列で、APのSSID設定を変更する機能ではありません。提供範囲・本番承認・利用規約の承認とも別です。

1. 現在の案内情報を読み込み、正式に決まった値だけ入力します。日時は日本時間・秒単位です。開始と終了は両方必要で、終了は開始より後にします。
2. 「変更案を保存」で返るファイル名を控えます。変更案は保存先の `configuration-history` に残ります。変更案の保存・適用は監査に記録します。
3. アプリと定期処理を停止します。旧版のプロセスも停止してください。新版は直接起動したapp/workerと監視起動の両方をロックで検査しますが、旧版の直接起動は検出できません。
4. 新版の専用Python環境で次を実行します。パスは実際の保存先へ置き換えます。

```powershell
python manage.py --home '保存先の絶対パス' apply-event-information --plan '保存先の絶対パス/configuration-history/event-info-plan-変更案ID.json'
```

5. 元設定・変更案・変更後設定を同じ履歴フォルダーへ新しい名前で保持します。他の変更後の古い案や別保存先の案は拒否します。日時が変わると受付期間IDを新しくし、以前の同意は元のIDのまま保持します。
6. アプリ・定期処理を起動し直し、日英・やさしい日本語の案内と受付状態を確認します。設定変更前のバックアップと秘密鍵は引き続き管理してください。履歴ファイルには元の運営設定が含まれるため外部へ無断共有しません。

設定の正本は既存の `config.json` です。受付日時は既存のルート項目を使い、表示用に別の日時を持ちません。任意の `event_information` に名称・SSID・窓口・会期確認状態を保持します。既存設定にこの項目がなくても利用できます。

## 未保存入力の保護

規約、引き継ぎ、当日の確認、案内情報が対象です。表示切り替えでは入力を保持します。置き換え更新・ログアウト・リンク移動では未保存入力の確認を出します。ブラウザー再読み込み・終了時は対応ブラウザーの標準確認を使います。ブラウザーによっては標準確認が抑止される場合があります。

保存が成功した送信時点の内容だけを保存済みとします。通信待ち中に追加で編集した内容や、別のフォームの未保存入力は残します。不明な保存結果を成功扱いしません。未保存内容はメモリーだけに置き、ブラウザー保存領域への自動保存や、未確認文面のサーバー自動保存は行いません。

ログイン期限切れ・認証喪失・権限の切り替え時は、保護のため入力と保護対象の表示を消去します。期限切れ後までの下書き復元は提供しません。必要な内容は期限内に明示的に保存してください。

## ログイン期限

サーバーの現在時刻とセッション期限から残り時間を計算します。PCの時刻設定には依存せず、2分以内に保存を促します。画面の更新や「期限を確認」はセッションを延長しません。新しいログインで新しいセッションを開始します。

画面の時計は操作支援で、サーバーの認証検査が最終判断です。端末のスリープ・通信遅延・バックグラウンドタブで通知が遅れることがあります。実際の期限切れはサーバーでも拒否します。

## 集計速度の確認

別の専用QA DBへ10,000 / 50,000 / 100,000件の合成同意記録を段階的に追加し、日本時間1日分の集計を各11回測定しました。対象日の件数が100 / 500 / 1,000件と一致することも確認しています。元の記録・QAデータ・ログを削除していません。

| 合成記録数 | 中央値 | 最大値（11回） |
|---|---:|---:|
| 10,000 | 57.86 ms | 69.16 ms |
| 50,000 | 69.47 ms | 91.16 ms |
| 100,000 | 93.17 ms | 126.28 ms |

このPCのMySQL・DB接続を含む集計関数の所要時間です。ブラウザー描画時間、AP負荷、ネット回線、来場者数、同時接続能力、同時リクエストの負荷試験は含みません。別の全体試験も実行中の測定であり、ディスクのキャッシュ状態は固定していません。各回のp95はnearest-rankで、11回では最大値と同じです。1秒は仮の確認基準で正式な性能要件ではありません。

現在は日付列の全件走査です。10万件時点の実測を踏まえてDB形式・索引を維持しました。さらに蓄積して遅くなった場合は、停止中・別DBで `accepted_at_utc` の索引を検討し、書き込みとバックアップ／復元への影響も再確認してください。実運用DBへ索引追加を自動適用しません。
