# TLS・中断復旧・保存形式の確認

0.8.0 / 2026年10月20日取りまとめ / MySQL・DB形式4

## 実NginxとTLS

公式配布のWindows版Nginx 1.31.7の署名を公式公開鍵で検証し、試験用CAとホスト名付き証明書を生成しました。CAは確認プログラムだけが信頼し、PC全体の証明書設定・DNSを変更していません。通信は127.0.0.1だけに限定しています。

25項目が合格しました。TLSの証明書チェーンとSAN、TLS 1.2、誤ったSANと未信頼CAの拒否、未知Hostの拒否、HTTPから固定ホストへの転送、公開側の管理経路拒否、管理側の実接続元IPによる制限、偽造転送ヘッダーの上書き、Origin・CSRF、Secure/HttpOnly/SameSiteのCookie、ログイン・画面取得・ログアウト・旧セッション拒否を確認しました。接続元制限は実際に127.0.0.2を送信元とする接続で拒否を確認しています。

試験用の転送設定はこの試験だけのものです。配布物のHTTPS設定生成機能は引き続き503を返す停止状態を生成します。学校のDNS、正式証明書、Linux、実AP、回線容量、IPv6の実機試験は未実施です。Windows版Nginxの公式資料はbetaでの制約を説明しているため、この結果から本番の処理能力を推定しません。

配布元: [Nginxダウンロード](https://nginx.org/en/download.html)、[公開鍵](https://nginx.org/en/pgp_keys.html)、[Windows版の制約](https://nginx.org/en/docs/windows.html)、[接続制限](https://nginx.org/en/docs/http/ngx_http_access_module.html)。

検証したZIPのSHA256: `7c717ccf861f8925be64431d06d57634512a5014bcc8d149f279928f5e8151bf`。署名鍵の指紋: `D6786CE303D9A9022998DC6CC8464D549AF75C0A`。Nginx本体と試験用の鍵はアプリ配布物に含めません。

## 処理中断と再実行

専用の空DBと保存先を各試験に作成しました。試験用子プロセスが指定した処理段階へ達したことを確認し、そのプロセスだけを強制終了しています。本体へ試験用の停止機能を追加していません。

| 中断対象 | 確認した段階と結果 | 再実行 |
|---|---|---|
| 分割バックアップ | 書き込み開始後に停止。.partialが残り、完成品にならず、検証は拒否 | 別名で作成し検証成功 |
| 分割バックアップの復元 | テーブル作成直後に停止。restore.incompleteが残り、アプリ起動を拒否 | 別の新しい空DB・フォルダーへ復元し記録を照合 |
| DB形式3から4への更新 | 最初の追加テーブル作成後に停止。upgrade.incompleteが残り、起動を拒否 | 停止状態で更新を再実行し、23テーブルと元監査記録を確認 |
| 復旧用一式 | tarメンバー2件を追加した後に停止。未完了暗号文と別置き鍵を保全、検証は拒否 | 別名・別の新しい鍵で作成し検証成功 |
| 容量設定更新 | 設定ファイルの置換直後・完了監査前に停止。有効なJSON、変更前設定、変更案、変更後設定、要求監査が残る | 現在設定から新しい案を作り適用、以前の履歴も保全 |

5項目とも成功しました。元記録、未完了物、失敗DB、試験ログを削除していません。完了後の状態マーカーだけを通常処理が解除します。これはプロセス中断試験です。物理的な電源断、ディスク故障、OSの書き込みキャッシュ喪失の保証は含みません。中断した復元先を使い回さず、調査用に保全してください。

## 保存形式の安全性点検

次を修正し、7件の追加回帰試験で確認しました。Fernet、分割フレーム、DB形式は変更していません。既存の正常な.fernet/.sffbackup/.sffkitは引き続き使用できます。

| 修正点 | 意図 |
|---|---|
| 検証前に復元元のSHA256を確定し、検証後・復元後と照合 | 最初の検証中に元ファイルが変更された場合も拒否 |
| tarの読み取り単位を512 bytesに限定し、暗号化終端まで読む | tar終端の先にある非ゼロの余分な内容を先読みで見落とさず拒否 |
| 大文字小文字だけ違うメンバー、予約名、末尾の空白・ドット、疎ファイルを拒否 | Windowsで同じファイルになる名前や特殊な展開を防止 |
| Windowsのreparse pointを検出 | ジャンクションやリンク経由の保存・収集を拒否 |
| DB更新にも停止状態と運営プロセスのロックを要求 | 稼働中の更新を拒否 |

7件には実際のWindowsジャンクション、認証付きだが不正なtar末尾、ファイル差し替え、大文字小文字の重複、予約名、稼働中の更新拒否を含みます。元の暗号文の改変・欠落・順序変更・別ファイル混在・終端の試験も全体試験に含めています。独立した専門家による暗号方式監査や形式の数学的証明を実施したものではありません。保存フォルダーと鍵はOS権限で保護し、同じOS管理者による同時改変を防げるとは扱いません。

## ログと適用範囲

アクセスログは時刻・メソッド・ステータスの固定形式で測定しました。Nginxのエラーログには接続元等が入る場合があり、アクセス権と保存容量の管理が必要です。全ログ・同意・監査・バックアップの自動削除停止を継続します。試験の証明書秘密鍵、QA接続情報、平文の復元物、試験DBは配布ZIPに含めません。

AP/RADIUSと本番受付は無効です。既存MySQL80、学校ネットワーク、VyOS、スイッチ、公開サイトに適用していません。
