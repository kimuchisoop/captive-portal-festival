# 0.11.0の実装と未確認範囲

ソース実装の記録です。アプリのimport、構文確認、試験、DB接続・適用、バックアップ/復元、ブラウザ、起動停止は行っていません。

## コードの接続

- workflow_database：31表の列/PK/InnoDB照合、4→5の停止中追加移行、途中マーカーと成功DDLのSHA記録、通常/保守の別資格情報、表/列GRANTの診断。DB.*・追加権限・不明式・有効roleを安全と断定しません。
- event_info_repository / workflow_routes：原本・内容SHA・対象・元configを照合し、追記イベントで状態を表現します。確認者の現在のsettings権限と期限/起動世代を検査し、自己確認を拒否します。保存/確認/取下げの正確な再送を先に照会します。
- apply-reviewed-plan：停止中の3ロック→対象ロック→DB書込ロック。適用試行を保存してからファイルを変更し、結果観測を追記します。途中失敗は自動適用再開せずreconcile-plan-applicationで照合します。旧--planだけの適用経路は拒否します。
- event_plan_import：CLIは64KiB以内の旧原本とconfigを照合し、失敗資料も保持。HTTPは資料のID/SHAを受け、同じ原本の重複・別対象・config変更・旧世代を拒否し、現在の本人による新しいsaved案を作ります。原本だけ残った成果物をGETから自動登録しません。
- archive_repository / archive_exports：対象プレビュー、本人の依頼だけの一覧/詳細/履歴、1本人1未完了、failed末端だけの再依頼。1つの読取スナップショットから1000件ずつコピーし、各短い書込TXで現在状態を確認します。完成前や復旧世代違いのコピーは公開しません。
- workflow_generation：fresh/restoredと世代を区別。復元は旧セッション等5表を稼働DBへ戻さず、新しい鍵、MFA再設定、許可/操作の安全化、原本26表の生ハッシュ照合、手動解除のreceiptを要求します。世代の因果関係と有効期限の時刻は別に扱います。
- workflow_alerts：6つの固定公開通知と、役割/所有者で絞った詳細。状態・版・集合の変化で世代を進め、確認済みを解除します。失敗した枝や循環を1つのreadyだけで解消せず、取得失敗を0件扱いにしません。復旧ガード中はHTTPを起動せず保護レポートで案内します。
- static/workflow-ui.js：変更案、旧案取り込み、本人の出力、担当作業の4領域。CSVは1000件単位、履歴はページ単位。APIの現在状態と過去成功を分け、APの通信許可を成功扱いにしません。

## 軽量化と計算量

同意コピーは最大1000件のバッチで読み書きし、executemanyで挿入します。型付きバックアップは暗号フレームと4MiB以下の1行で処理し、DB全量をメモリへ展開しません。復旧キットの履歴ファイルは1MiBずつコピーします。一覧はカーソルと件数上限で取得し、出力一覧のsnapshot/queued情報はまとめて読みます。新しい画面の定期ポーリングは追加していません。

監視は全体の未解消条件を求めるため、出力依頼の小さな依存グラフを保持します。メモリは依頼数に比例し、無制限の件数に一定メモリを保証するものではありません。CSVの先頭ページは封印照合のため固定コピー全体を読みます。書込ロック、DB負荷、ピークメモリ、所要時間、承認済み間隔の生存情報（提案10秒）を含む性能は未測定です。

## 形式5の保存・復元

DB形式5 / 平文festival-wifi-stream-backup-v2 / codec 1 / 暗号コンテナーSFFRAME1 / 復旧用一式festival-recovery-kit-v2です。31表の契約はworkflow-contract.json、実DDLはschema-v5.sql、追加DDLはfeatures-v5.sqlです。旧schema.sqlは変更していません。

SQL整数は正規十進文字列、SQL NULLはJSON null、JSON列は正規化したJSON文字列にします。全表を同じ読取TXで保存し、行/表/全体終端と暗号EOFを検査してから完成名へ移します。失敗途中物を保持します。復元は空DB・新homeだけです。自己参照retryを2段階で戻し、原本26表のハッシュを照合した後に安全化を記録します。

CSVコピーのrow_sha256は、ordinalとITEM_KEYSの10項目のcanonical JSONに対するSHA-256です。rows_sha256はordinal順のrow_sha256 ASCII+LFの連結に対するSHA-256です。BOM・CRLF・数式先頭対策はCSV生成時だけ適用し、元DBの値は変更しません。ページ生成の監査は端末への受信完了の証明ではありません。

## 互換と未確認

形式4は起動拒否です。旧形式の認証済み読取は残しますが、旧形式の復元/移行は対応する旧版で行う別工程です。形式5の受付値と列/権限/復旧/トリガー/DEFINERは試験していません。旧形式4の試験群をそのまま本候補の合格判定に使いません。

記録を消す処理、AP設定、本番有効化、資格情報の配布は追加していません。画面/CLIが存在することと、動作が確認済みであることは区別します。
