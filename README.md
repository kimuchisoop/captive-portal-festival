# 学校祭ゲストWi-Fi 同意型キャプティブポータル

学校祭（2026年10月31日・11月1日開催）の来場者向けに作った、ゲストWi-Fiの同意画面と管理システムです。
来場者が利用規約に同意すると、会場のルーター（VyOS）に通信許可を登録し、2時間で自動的に接続を終了します。

- 版：0.11.10-rc1
- 詳しい資料：[docs/ガイド.md](docs/ガイド.md)（導入・DB設定・FreeBSD配置・運用・復旧・試験結果）
- ルーター側の作成手順：[docs/キャプティブポータル作成手順.md](docs/キャプティブポータル作成手順.md)

## しくみ

```text
来場者のスマホ
   │ Wi-Fiに接続（AP） → 未許可の間はWebアクセスが同意画面へ案内される
   ▼
core-rt（VyOS ルーター）
   │ 許可グループ PORTAL-AUTHED に入ったIPだけインターネットへ通す
   ▼
nginx（HTTPS）
   ▼
アプリ（Python / Flask + Waitress、127.0.0.1のみで待ち受け）
   │ ① 同意を保存 → ② VyOSのHTTPS APIで来場者のIPを許可グループへ登録
   │ ③ 2時間後（または17:00）に許可を自動で解除
   ▼
MySQL 8（同じサーバー、127.0.0.1のみ）
```

## 主な機能

**来場者向け**
- 利用規約への同意画面（日本語・英語・やさしい日本語、文字サイズと配色の切り替え）
- 同意から120分で自動切断。提供時間（10:00〜17:00）を過ぎると残り時間があっても終了
- 開場直後の混雑時は、待ち時間の案内（HTTP 429）を出し、同意を送り直さないよう案内する
- OSの接続確認に応えるCAPPORT API（RFC 8908）

**運営者向け（管理画面）**
- 役割ごとの権限（設定管理者・運用担当・記録担当・閲覧のみ）
- 認証アプリによる2段階認証、ログイン試行の制限（第三者が管理者を締め出せないよう、接続元ごとに判定）
- 記録のCSV出力は、依頼者とは別の担当者の承認が必要（二者確認）
- 暗号化バックアップと、新しい空のDBへの復元確認

**ルーター連携（VyOS）**
- 同意した来場者のIPを、VyOSのHTTPS APIで許可グループへ登録・解除
- 開場直後の同時同意に備えて、登録をまとめて処理（一括commit）
- 応答のなかった許可は取り消しを予約し、期限切れの解除と再同意が重なっても許可を失わない

## 技術

| 分野 | 使ったもの |
|---|---|
| アプリ | Python 3.12、Flask、Waitress |
| DB | MySQL 8（最小権限のアカウントを専用ツールで生成） |
| 配置先 | FreeBSD 15.1 amd64、nginx、pf（ファイアウォール） |
| ネットワーク | VyOS（HTTPS API）、VLAN分離 |
| 配布 | PyInstallerで単体の実行ファイル化（Windows / Linux / FreeBSD）、minisignによる署名の手順 |
| 試験・CI | unittest（226件、MySQLを使う試験を含む）、GitHub Actions |

## 安全面で工夫したこと

- **失敗を成功に見せない**：ルーター連携が無効・未接続のときは「通信許可なし」として扱い、許可できたふりをしない
- **初期状態は安全側**：受付停止・ルーター連携無効で起動し、設定ファイルを書き換えるだけでは本番にならない
- **DBは外から触れない**：MySQLは127.0.0.1だけで待ち受け。別マシンに置く構成ではTLSと証明書の検証を必須にした
- **秘密情報を残さない**：パスワードはコマンド引数に書かず対話入力。接続情報・鍵はリポジトリに入れない（雛形は`CHANGE_ME`）
- **配布物の改ざん確認**：ファイルのハッシュ一覧（release-manifest）と署名で、配置前に照合する

## 現状

- **VyOS連携**：会場の実機（core-rt）で、来場者への通信許可を実施済み。公開版の設定は初期状態（無効）にしてある
- **AP連携（外部ポータル＋RADIUS）**：使っていない（未実装）。通信許可はVyOS連携で行った
- 資料（ガイド・RELEASE.md）には、会期前の時点の記録が残っている部分がある

## 動かし方（概要）

```text
festival-wifi --home <保存先> init --db-config <runtime.json> --maintenance-db-config <maintenance.json>
festival-wifi --home <保存先> add-admin <利用者名> --role settings
festival-wifi --home <保存先> serve      # 別プロセスで worker も起動
festival-wifi --home <保存先> worker
```

接続設定は`server/runtime.example.json`などをコピーして作ります。MySQLの準備、ソースからの起動、FreeBSDへの配置は[ガイド](docs/ガイド.md)の3〜5章にあります。
